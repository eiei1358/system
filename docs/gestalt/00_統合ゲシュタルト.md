## 1. システムの目的（一言で）

社員間の物品（書籍・IT 機器など）の**譲渡（やりとり）情報を仲介する社内フリマ**。
有償・無償・オークションのいずれにも対応。**物品や金銭の受け渡し自体には関与しない**
（システムは「情報のマッチング」と「証跡管理」までを担う）。

## 2. 登場人物（アクター）

| アクター | 役割の要約 |
|---|---|
| **社員** | 物品の出品・検索・応募/入札・メッセージ・通報・譲渡完了登録・QR 状況確認 |
| **管理者** | 社員情報管理・カテゴリ/検索キー管理・監視/NG ワード・削除/利用制限・統計閲覧 |
| **人事システム**（外部） | 新入社員情報を CSV で連携（バッチ的な外部アクター） |

## 3. ドメインの中心概念（エンティティの種）

```
社員(Employee) ──出品──> 物品(Item) <──応募/入札── 社員(Employee)
                              │
                              ├─ 写真(Photo) 複数
                              ├─ カテゴリ(Category) 1..*
                              ├─ 検索キー(SearchKey) 0..*
                              ├─ 価格条件(無償/有償/オークション, 価格交渉可否, 受渡方法)
                              ├─ 商品状態(新品/新品同様/中古/ジャンク)
                              └─ 登録期限(Deadline)

応募/入札 ──成約──> 譲渡(Transfer/取引)
                       ├─ 譲渡ID（ランダム・推測不能）→ QRコード/状況確認URL
                       ├─ 状態: 出品中 → 成約済み → 譲渡完了
                       └─ メッセージ(Message) ←→ 当事者のみ公開

管理: NGキーワード, 通報, 利用制限, 統計, 監査ログ(最終ログイン日時 等)
```

### 物品・譲渡の状態遷移（ライフサイクル）

```
[出品中] ──応募あり──┐
   │                 ├─(出品者が成約者選択 / オークションは期限で自動)→ [成約済み]
   │                 │
   ├─登録期限切れ──> [期限切れ]（応募不可。再登録で新期限を設定可）
   │
[成約済み] ──双方が譲渡完了登録──> [譲渡完了]
   （片方のみ登録時は「相手の完了待ち」で保持）
```

## 5. 横断的な要件（非機能・ポリシー）

- **セキュリティ**: パスワードは暗号化保存／仮パスワードはランダム生成・メール通知／
  譲渡 ID はランダムで推測不能／3 回連続認証失敗でアカウント無効化。
- **強制変更ポリシー**: 仮パスワードログイン時・3 か月以上未変更時はパスワード変更を強制。
- **通知**: メッセージ受信・成約・パスワード系イベントはメールでリアルタイム通知。
- **可視性**: メッセージは当事者（送受信者）のみに公開。通報は管理者のみに通知。
- **監視**: 曖昧検索による事後監視 ＋ NG キーワードによる事前ブロックの二段構え。
- **統計**: 数値だけでなくグラフによる視覚的提供が望ましい。
- **UX（任意）**: 余裕があればレスポンシブ対応でスマホ操作を容易に。機能追加提案歓迎。

## 6. 読み取れた論点・不整合（実装前に要確認）

ユースケース記述（学生作成のドラフト）には以下のゆらぎ・要確認点があります。
詳細は [`02_ユースケース_ゲシュタルト.md`](02_ユースケース_ゲシュタルト.md) の「品質メモ」に記載。

1. **ID の重複/形式ゆれ**: UC005 のファイル内 ID が「UC001」になっている。
   400 番台以降は `UC` 接頭辞なしの数値 ID（401, 402, 501…）で統一されていない。
2. **システム名のゆれ**: 702/703 が「日記システム」、その他は「フリマシステム/フリマ社内システム」。
   チーム名も「やまぐ/ヤマグ/ヤマぐ/ヤマグチーム」と不統一。
3. **要件書の番号バグ**: 機能の見出しが「8.」を 2 回使用（メッセージ／物品登録）。以降ずれている。
4. **認証方式のゆれ**: UC001 は「パスワードのみ入力」、UC005/UC101 は「メールアドレス＋パスワード」。
   ログインの識別子（社員番号 or メール）を確定する必要あり。
5. **未カバー**: ログアウト、期限切れ物品の再登録フロー、価格交渉の具体的フロー。
